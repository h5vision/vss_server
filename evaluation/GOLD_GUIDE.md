# 시험지(문항) 만들기 안내 — 코드만 읽을 줄 알면 됩니다

우리 서버는 "이 기능은 어디서 처리하나요?" 같은 질문을 받으면 레포에서 관련 코드를 찾아 근거와 함께 답합니다.
그 **찾는 실력을 점수로 재려면 시험지**가 필요합니다. 시험지는 **질문**과 **그 답이 있는 자리**를 짝지은 목록입니다.
이 문서는 그 시험지를 쓰는 사람을 위한 안내입니다. AI 나 검색을 몰라도 됩니다. 필요한 건 그 레포의 코드를 열어 볼 수 있는 것뿐입니다.

---

## 1. 무엇을 내면 되나 — 표 한 장

아래 다섯 칸짜리 표를 채워서 주시면 됩니다. 엑셀, 구글 시트, 마크다운 표 어느 것이든 좋습니다. JSON 으로 바꾸는 일은 이쪽에서 합니다.

| 번호 | 질문 | 답이 있는 파일 | 그 자리 이름 | 답 한 줄 (선택) | 메모 |
|---|---|---|---|---|---|
| 1 | 채팅 요청을 받는 API 들을 한데 묶어 등록하는 곳은 어디인가요? | `backend/api/v1/chat.py` | `create_chat_router` | v1 채팅 라우터를 만들어 앱에 붙인다 | |
| 2 | 작업 중인 코드와 서버에 저장된 스냅샷을 비교하는 건 어디서 하나요? | `backend/api/v1/snapshots.py` | `compare_snapshot` | HEAD 가 같아도 작업 트리는 따로 본다 | |
| 3 | 로그인 토큰을 만드는 함수는 어디에 있나요? | (없음) | | | 이 레포에는 로그인이 없다 |

- **답이 있는 파일**: 레포 맨 위 폴더부터의 경로. `/` 로 구분합니다.
- **그 자리 이름**: 그 파일 안에서 답이 되는 **함수·클래스·상수 이름**입니다. 3번에서 설명합니다.
- **답 한 줄**: 이 질문을 받은 선배 개발자가 뭐라고 대답할지, 그 대답을 한 문장으로 적는 칸입니다. 비워 둬도 됩니다.
  왜 있느냐면, 지금 채점은 "서버가 **맞는 파일을 펼쳤는가**" 까지만 봅니다. 서버가 그 파일을 보고 실제로 **쓴 대답이 맞는지**는 아무도 채점하지 않습니다. 대답을 채점하려면 모범 답안이 있어야 하는데, 그게 이 칸입니다. 이 칸이 채워지면 나중에 서버의 대답과 나란히 놓고 맞았는지 볼 수 있습니다.
- 답이 여러 군데면 줄을 나눠 같은 번호로 두 번 적으면 됩니다. **같은 코드가 두 벌 있으면(옛 파일과 새 파일에 같은 함수) 둘 다 적습니다.** 하나만 적으면 서버가 다른 쪽을 찾았을 때 틀린 걸로 셉니다.
- **답이 없는 질문**은 파일 칸에 "(없음)" 이라고 적습니다. 6번에서 설명합니다.

## 2. 몇 개나 필요한가

레포 하나에 **150개 — 답이 있는 질문 120개, 답이 없는 질문 30개**입니다. 지금 있는 시험지는 레포당 40~61개라 "너무 적다" 는 말을 들었습니다.

왜 이만큼이냐면, 문제 수가 적을수록 **한 문제가 점수를 크게 흔들어서** 진짜 좋아진 건지 우연인지 구분이 안 되기 때문입니다.

| 답이 있는 문제 수 | 한 문제의 무게 | 점수의 오차 범위 (80점 기준) | 무엇을 말할 수 있나 |
|---:|---:|---:|---|
| 10 | 10점 | ±25점 | 아무것도 |
| 30 (지금) | 3.3점 | ±14점 | 크게 좋아진 것(15점 이상)만 |
| **120** | **0.8점** | **±7점** | 5~10점 차이도 판단 가능 |

150개를 한 번에 채우기 어려우면 **답 30개 + 없는 10개를 먼저** 주십시오. 거기서부터 측정이 시작되고, 나머지는 이어서 더하면 됩니다.

여러 사람이 나눠 쓸 때는 **폴더나 기능 영역으로 나눠 맡습니다.** 같은 자리를 두 사람이 내면 한 문항으로 칩니다. 세 사람이 한 레포를 맡으면 한 사람이 **답 있는 것 40개, 없는 것 10개**입니다. 사람 수가 다르면 md 가 나눠서 알려 줍니다.

## 3. "그 자리 이름" 이 무엇이고 왜 필요한가

코드에서 `def 이름(...)` 이나 `class 이름:` 으로 시작하는 줄이 있습니다. 그 **이름**이 "그 자리 이름" 입니다. 이 레포 안에서는 이걸 **심볼**이라고도 부릅니다.

```python
class SnapshotService:            ← 클래스 이름: SnapshotService
    def compare(self, a, b):      ← 함수 이름: compare  (클래스 안에 있으면 SnapshotService.compare 라고 적어도 됩니다)
```

왜 줄 번호가 아니라 이름을 적느냐면 두 가지입니다.

- **줄 번호는 코드가 한 줄만 바뀌어도 어긋납니다.** 이름은 남습니다.
- 서버는 코드를 함수 단위로 잘라서 기억하고, 조각마다 그 이름을 붙여 둡니다. 이름을 적으면 **"정확히 그 조각을 찾았는가"** 를 기계로 채점할 수 있습니다.

찾는 법은 간단합니다. 답이라고 생각한 코드 줄에서 **위로 올라가다가 처음 만나는 `def` 나 `class` 의 이름**을 적으면 됩니다. 답이 `DEFAULT_RETRY = 3` 같은 **상수나 설정 변수**면 그 변수 이름을 적습니다.

파이썬이 아닌 파일(설정 파일, 문서, 자바스크립트 등)은 함수 이름이 없을 수 있습니다. 그럴 때는 **그 자리에만 있는 낱말 하나**(설정 키 이름, 제목 문구 등)를 적어 주십시오. 검사할 때는 "그 파일 안에 그 글자가 있는가" 만 봅니다.

## 3-1. 질문 안에 이름을 쓸 때는 백틱(`)으로 감쌉니다 — 왜 그런지부터

질문에는 두 부류가 있습니다. **이름을 알고 묻는 질문**("`create_chat_router` 는 어디 있나요?")과 **이름을 모르고 하는 일로 묻는 질문**("채팅 API 를 등록하는 곳이 어디죠?")입니다. 실제 사용자는 대부분 뒤쪽입니다. 그런데 두 부류는 서버가 찾는 방식이 다릅니다.

- 이름을 모르는 질문은 **뜻이 비슷한 코드**를 찾습니다.
- 이름을 아는 질문은 그 위에 **"그 이름이 붙은 코드 조각을 앞으로 당기는" 기능**이 하나 더 있습니다. 우리가 따로 만든 기능인데, 아직 도움이 되는지 해가 되는지 재 본 적이 없습니다.

이걸 재려면 시험지에서 **두 부류를 갈라서 따로 채점**해야 합니다. 그런데 컴퓨터는 질문 문장에서 어느 낱말이 함수 이름이고 어느 낱말이 그냥 영어 단어인지 모릅니다. `run`, `main`, `process` 같은 건 둘 다 될 수 있습니다. **그래서 사람이 표시를 해 줘야 합니다.** 그 표시가 백틱입니다. 키보드에서 숫자 1 왼쪽에 있는 글자입니다.

- 좋음: "`` `create_chat_router` `` 는 어디에 있나요?" — 이름을 안다고 표시됨
- 나쁨: "create_chat_router 는 어디에 있나요?" — 이름인지 단어인지 컴퓨터가 못 가림

규칙은 둘뿐입니다.

1. **이름을 알고 묻는 질문**이면 그 이름을 백틱으로 감쌉니다.
2. **이름을 모르고 묻는 질문**이면 이름을 아예 넣지 않습니다. 하는 일로만 씁니다.

이 둘만 지키면 종류 표시는 이쪽에서 자동으로 붙습니다.

## 4. 좋은 질문과 나쁜 질문 — 사람이 꼭 해야 하는 부분

여기서 시험지의 값어치가 갈립니다.

**좋은 질문**
- 처음 온 사람이 물을 법한 말투로 씁니다. "하는 일" 로 묻습니다.
  - 좋음: "작업 중인 코드랑 서버에 저장된 걸 비교하는 건 어디서 하나요?"
  - 나쁨: "SnapshotComparisonService 클래스의 위치는?"
- 답이 한두 군데로 정해집니다. "설정은 어디 있나요?" 는 열 군데가 다 답이라 채점이 안 됩니다.

**제일 조심할 것 — 코드 문장을 그대로 베끼지 않기**

코드에 이런 주석이 있다고 합시다.

```python
class RedisCoordinator:
    """Shared metrics and reliable Redis Stream queue for all API replicas."""
```

이걸 보고 "모든 API 복제본을 위한 공유 지표와 Redis Stream 큐는 어디 있나요?" 라고 쓰면, 질문과 답이 거의 같은 문장이 됩니다. 검색은 당연히 맞힙니다. 그런데 **실제 사람은 그렇게 안 묻습니다.** 이런 문항만 모이면 점수는 높은데 실제로는 못 찾는 시험지가 됩니다.

> 사람 말로 바꾸면: "서버를 여러 개 띄웠을 때 서로 상태를 공유하는 건 어떻게 하나요?"

## 5. 어떤 종류를 섞어야 하나

한 종류만 있으면 한쪽 실력만 재게 됩니다. 아래를 골고루 넣어 주십시오. 지금 특히 부족한 것은 앞의 셋입니다.

| 종류 | 예 | 왜 필요한가 |
|---|---|---|
| **이름 없이 하는 일로 묻기** | "결제가 실패하면 몇 번까지 다시 시도하나요?" | 이름을 모르는 사람이 대부분입니다. 지금 가장 부족한 종류입니다 |
| **흐름 묻기** | "요청이 들어오면 어디서 시작해서 어디로 넘어가나요?" | 답이 두세 군데에 걸칩니다. 여러 줄로 적어 주십시오 |
| **테스트 코드 묻기** | "결제 검증 테스트는 어디 있나요?" | 서버가 테스트 파일을 뒤로 미루는 기능이 있어서, 그게 손해를 주는지 재야 합니다. 3~5개면 됩니다 |
| 이름을 알고 묻기 | "`create_access_token` 은 어디 있나요?" | 이름 검색이 되는지. **이름은 백틱으로** (3-1). 특히 `run`·`main` 같은 **한 낱말 이름**, 클래스 안의 **메서드 이름**(`Service.run`), 긴 문장 속에 이름이 하나 섞인 질문이 값어치 있습니다. 지금 시험지의 이름 질문은 너무 쉬워서 이 기능이 도움이 되는지 못 잽니다 |
| 문서가 답인 질문 | "이 프로젝트를 실행하려면 어떻게 하나요?" | README 나 문서 파일이 정답인 경우. 파일 칸에 그 문서 경로 |
| 문서와 코드가 다른 질문 | "목록 조회의 최대 개수는 몇이에요?" (README 는 500, 코드는 10000) | 문서 설명이 낡은 자리. 정답은 **코드** 쪽으로 적고, 메모에 "README 와 다름" 을 씁니다. **일부러 만들지 않습니다.** 코드를 읽다가 원래 그런 자리를 발견했을 때만 넣고, 없으면 0개여도 됩니다. 레포를 고쳐서 만들면 안 됩니다 |
| **한 파일 안 여러 함수에 걸친 질문** | "결제 한 건이 검증부터 전송까지 어떻게 흘러가나요?" (한 파일의 함수 셋) | 서버가 같은 파일 조각을 앞자리에 2개까지만 두는 기능이 있어서, 그게 손해를 주는지 재야 합니다. 정답을 여러 줄로 적습니다. 3~5개면 됩니다 |
| 설정값·상수 묻기 | "재시도는 기본 몇 번인가요?" | 답이 함수가 아니라 상수 한 줄인 경우. 그 자리 이름에 변수 이름 |
| **답이 없는 질문** | "로그인 토큰은 어디서 만드나요?" (이 레포에 로그인이 없을 때) | 6번 |

## 6. 답이 없는 질문도 10개쯤 필요합니다

서버는 **모르면 모른다고 해야** 합니다. 아무 코드나 가져와 그럴듯하게 지어내는 게 제일 나쁜 실패입니다. 그래서 일부러 답이 없는 질문을 넣습니다.

좋은 "답 없는 질문" 은 **그럴듯하게 들리는 질문**입니다.
- 좋음: "로그인한 사용자에게 줄 토큰을 만드는 함수는 어디에 있나요?" → 다른 프로젝트에는 흔한 기능이라 진짜처럼 들리지만 이 레포에는 없습니다
- 나쁨: "고양이 사진은 어디 있나요?" → 너무 뻔해서 시험이 안 됩니다

## 7. 하면 안 되는 것

- **검색 대상에서 빠진 폴더의 파일을 정답으로 하지 않습니다.** 서버가 아예 안 읽는 폴더가 있습니다. 레포마다 목록이 다르니 시작할 때 md 에게 받으십시오. 예를 들어 `api_test` 는 `tests/`, `admin/`, `.snapshot-admin-backup/`, `data/` 입니다. 그 안의 것을 정답으로 하면 무조건 틀립니다. 반대로 그 폴더 내용을 **답 없는 질문**으로 내는 건 환영입니다.
- 코드가 그 뒤로 바뀌면 자리가 어긋납니다. **md 가 알려 준 시점(커밋)의 코드**를 보고 쓰십시오.
- 한 질문에 정답이 열 군데인 질문은 빼십시오.

## 8. 다 쓰면

표 파일을 md 에게 주시면 됩니다. 이쪽에서 검사 프로그램을 돌려 세 가지를 확인합니다.

1. 그 파일이 정말 있는가
2. 그 파일 안에 그 이름이 정말 있는가
3. 빠진 폴더의 파일을 정답으로 쓰지 않았는가

걸리는 게 있으면 그 줄만 표시해서 돌려드립니다. 오타나 경로 한 칸 차이가 대부분이라 고치는 데 오래 걸리지 않습니다.
문항의 종류 표시(이름을 알고 물었는지, 답이 없는지 등)는 이쪽에서 붙입니다. 백틱 규칙(3-1)만 지켜 주시면 됩니다.
